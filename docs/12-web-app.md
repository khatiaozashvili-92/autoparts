# 12 — Web Platform

> წყარო: PRD §82–83, §55, §80. სტეკი: Next.js (App Router) + React + TypeScript.

---

## 1. დანიშნულება

ვები აკეთებს ორ რამეს, რასაც მობილური ვერ აკეთებს:

1. **ახალი მომხმარებლების მოზიდვა ძებნის სისტემებიდან** — „BMW 228i საქარე მინა“
   Google-ში აკრეფილი უნდა მიდიოდეს ჩვენს გვერდზე;
2. **სწრაფი გამოყენება ინსტალაციის გარეშე** — ერთჯერადი მყიდველი აპს არ ჩამოტვირთავს.

ამიტომ ვების მთავარი ტექნიკური მოთხოვნა არის **SSR + SEO**, არა ფუნქციური სიახლე.
ფუნქციურად ის მობილურის სრული ანალოგია.

## 3. Responsive (§82)

| Breakpoint | ლეიაუტი |
|------------|---------|
| < 640px | ერთი სვეტი, ქვედა ნავიგაცია — mobile app-ის ანალოგი |
| 640–1024px | ორი სვეტი |
| > 1024px | სამი სვეტი: ფილტრები · შედეგები · მანქანის კონტექსტი |

**მანქანის კონტექსტი ყოველთვის ხილულია** დესკტოპზე:

│ 2.0 Turbo · ავტომატური       │

ეს არის პროდუქტის ცენტრალური იდეის მუდმივი შეხსენება (§74 v1): მომხმარებელი არ ეძებს
ნაწილს — ის ეძებს **თავისი მანქანის** ნაწილს.

## 4. Product page — SEO (§54)

```html
<title>საქარე მინა BMW 2 Series (F22) 2014-2021 — Pilkington | autoparts</title>
<link rel="canonical" href="https://…/p/windshield-bmw-f22-pilkington" />
<link rel="alternate" hreflang="ka" href="…/ka/p/…" />
<link rel="alternate" hreflang="en" href="…/en/p/…" />
```
```json
{ "@context":"https://schema.org", "@type":"Product",
  "name":"Windshield — BMW 2 Series F22",
  "sku":"…", "mpn":"51317279769",
  "brand": {"@type":"Brand","name":"Pilkington"},
  "offers": {"@type":"AggregateOffer","lowPrice":"420.00",
             "priceCurrency":"GEL","offerCount":3,
             "availability":"https://schema.org/InStock"} }
```

გვერდის შიგთავსი (§54): სახელი · სურათები · ბრენდი · **OEM** · part number ·
თავსებადობა · ტექნიკური მახასიათებლები · მდგომარეობა · გარანტია · გამყიდველი ·
ლოკაცია · ფასი · მარაგი · expected availability · **დაბრუნების და გაუქმების წესები**.

### 4.1 ორი რეჟიმი ერთსა და იმავე გვერდზე

| | მანქანა არჩეულია | მანქანა არ არის |
|---|------------------|-----------------|
| Fitment | ✅ „თავსებადია თქვენს BMW 228i-თან“ | „შეამოწმეთ თქვენს მანქანაზე“ + VIN ველი |
| Offers | სრული სია ფასებით | ფასების დიაპაზონი |
| ღილაკი | „ყიდვა“ | „ჩემი მანქანის შემოწმება“ |

**Google-იდან შემოსული მომხმარებელი მანქანის გარეშე მოდის.** მას ვერ ვეტყვით
„ჯერ VIN შეიყვანე“ — გავა. სამაგიეროდ ვაჩვენებთ პროდუქტს და **fitment-ის ნაცვლად
მოწვევას**. ეს არ არღვევს R1-ს: ყიდვა მანქანის გარეშე შეუძლებელია, მხოლოდ დათვალიერებაა.

## 5. Home (§83)

```
┌───────────────────────────────────────────────┐
│           იპოვე ზუსტი ნაწილი                  │
│           შენი ავტომობილისთვის                │
│                                               │
│   ┌─────────────────────────┬──────────────┐  │
│   │ VIN (17 სიმბოლო)        │ ავტომობილის  │  │
│   │                         │  დამატება    │  │
│   └─────────────────────────┴──────────────┘  │
│                                               │
│   VIN → ზუსტი მანქანა → თავსებადი ნაწილები    │

└───────────────────────────────────────────────┘
```
შესული მომხმარებლისთვის Home = Garage + ძებნა (მობილურის §3-ის ანალოგი).

## 6. Checkout

```
1. კალათა        → პროდუქტი, მანქანა, თავსებადობა, რაოდენობა
2. აღების ადგილი → პარტნიორის მისამართი, სამუშაო საათები, ინსტრუქცია
3. გადახდა       → provider
4. დადასტურება   → შეკვეთის ნომერი + QR
```
რეზერვაციის 15-წუთიანი ტაიმერი ჩანს 2–3 ნაბიჯზე.
**MVP-ში მიწოდების არჩევანი არ არსებობს** — მხოლოდ pickup (§1, §48).
`delivery_method` ველი DB-შია, UI-ს ბიჯი P1-ზე ჩნდება.

## 7. i18n (§80)

```
apps/web/app/[locale]/…      →  /ka/… , /en/…
```

| წესი |
|------|
| ყველა ტექსტი translation key-ით — hardcoded სტრიქონი აკრძალულია |
| `if (country === 'GE')` business logic-ში **აკრძალულია** |
| ფული — `Intl.NumberFormat(locale, { currency })` |
| თარიღი — `Intl.DateTimeFormat`, მომხმარებლის timezone |
| მისამართის ფორმატი — country-ს კონფიგურაციიდან, არა hardcoded |

**CI-ს შემოწმება:** lint წესი, რომელიც JSX-ში literal ტექსტს ვერ უშვებს, და
ტესტი, რომელიც ამოწმებს ka/en key-ების სრულ დაფარვას.

## 8. წარმადობა

| მეტრიკა | სამიზნე |
|---------|---------|
| LCP | < 2.5 წმ |
| INP | < 200 მწმ |
| CLS | < 0.1 |
| Search response | < 2–3 წმ (§73) |
| Product page | < 1 წმ |

- Product/category — SSG + ISR (revalidate 60წმ)
- **Offers — ყოველთვის ახალი, არასოდეს ქეშირებული** (R2)
- სურათები — `next/image`, AVIF/WebP
- Bundle budget — 200KB gzipped საწყისი JS

> Offers-ის ქეშირება ყველაზე დიდი ცდუნება და ყველაზე საშიში შეცდომაა: ქეშირებული
> „In Stock“ პირდაპირ არღვევს R2-ს და აზიანებს `Inventory Accuracy` KPI-ს.

## 9. ხელმისაწვდომობა

WCAG 2.1 AA: კლავიატურით სრული ნავიგაცია · focus indicator · ARIA labels ·
კონტრასტი ≥ 4.5:1 · `prefers-reduced-motion`.

**Fitment-ის სტატუსი არასოდეს გადმოიცემა მხოლოდ ფერით.** ✅/⚠️/❌ თან ახლავს ტექსტი —
ეს ერთდროულად ხელმისაწვდომობის მოთხოვნაა და §55-ის მკაფიოობის მოთხოვნა.

## 10. საერთო კოდი მობილურთან

| პაკეტი | შიგთავსი |
|--------|----------|
| `packages/core` | ტიპები, enum-ები, `Money`, identifier normalization |
| `packages/api-client` | typed API კლიენტი |
| `packages/fitment` | fitment-ის ლოგიკა (preview/ახსნისთვის) |
| `packages/i18n` | translation keys |
| `packages/ui` | დიზაინის ტოკენები (ფერი, ტიპოგრაფიკა, spacing) |

`packages/ui` **კომპონენტებს არ აზიარებს** web-სა და React Native-ს შორის — მხოლოდ
ტოკენებს. საერთო კომპონენტის ფენა ორივეს აფერხებს; საერთო ტოკენები კი ვიზუალურ
ერთიანობას ინარჩუნებს იაფად.
